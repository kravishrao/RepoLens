RepoLens: Evidence-Grounded Python Repository Intelligence via Structure-Aware Hybrid Retrieval, Graph Context Expansion, and Ground-Truth Citation Verification

A Verifiable Multi-Hop Code Understanding System for Enterprise Software Engineering
K Ravish Rao, Manoj Kanur, Research Collaborators
Department of Computer Science and Engineering, PES University, Bangalore, India
Capstone Project & Technical Research Report | Integration Branch: develop (v0.1.0)
Abstract—Modern Large Language Models (LLMs) and standard Retrieval-Augmented Generation (RAG) pipelines demonstrate severe failure modes when deployed across large-scale software codebases. Fixed-size chunking strategies systematically fragment semantic structures across arbitrary byte offsets, induce token bleed, blind non-local caller-callee hierarchies, and synthesize hallucinated line references that do not correspond to actual source files on disk. To address these critical limitations, this paper presents RepoLens, a verifiable repository-level code intelligence system designed for comprehensive Python codebase analysis. RepoLens eliminates arbitrary chunking by decomposing Python source code into syntax-valid Abstract Syntax Tree (AST) CodeUnit objects (functions, methods, classes) preserving fully qualified lexical namespaces, parameters, and docstrings. RepoLens couples multimodal hybrid retrieval (BM25 lexical search and dense Sentence-Transformer vector embeddings combined via Reciprocal Rank Fusion and Cross-Encoder reranking) with a directed multigraph (CodeGraph) capturing CONTAINS, IMPORTS, CALLS, and INHERITS relationships to achieve deterministic k-hop context expansion across file boundaries. Furthermore, RepoLens introduces a cyclic LangGraph state machine orchestrating iterative multi-tool investigation, culminating in a strict citation verification engine that physically cross-examines every synthesized citation against filesystem line ranges and AST symbol boundaries. We conduct a rigorous empirical benchmark over 100 standardized questions across five canonical open-source repositories (Requests, Flask, Click, FastAPI, and Pydantic), evaluating six progressive architectural baselines (B0 through B5). Empirical findings demonstrate that RepoLens improves Citation Precision from 46.0% in naive chunked RAG to 100.0%, elevates multi-hop Recall@5 from 37.4% to 100.0%, and delivers zero false-positive citations with an average query latency of 728 ms.
Index Terms—Repository-Level Code Understanding, Retrieval-Augmented Generation (RAG), Abstract Syntax Tree (AST), Code Property Graph, LangGraph Agent, Citation Verification, Empirical Software Engineering.

I. Introduction

Contemporary software engineering operates at scales of unprecedented complexity. Enterprise and production software repositories routinely span hundreds of modules, tens of thousands of functions, deeply nested object-oriented class hierarchies, and intricate non-local dependency graphs. Empirical studies across industrial engineering teams reveal that software developers spend upwards of 70% of their daily cognitive effort reading, navigating, and comprehending existing source code rather than authoring novel logic [1], [2]. When onboarding new developers, performing security audits, diagnosing cross-module regressions, or conducting architectural refactoring, engineers require accurate, verifiable answers regarding how individual components interact across repository boundaries.

Recent advances in Large Language Models (LLMs) and Retrieval-Augmented Generation (RAG) have demonstrated promising conversational capabilities. However, off-the-shelf RAG architectures frequently fail when applied to repository-scale software systems [3], [4]. Standard document RAG relies on fixed-size sliding text windows (e.g., 500 tokens with 50-token overlap). While adequate for linear prose, fixed chunking inflicts catastrophic damage upon code semantics: function bodies are cleaved in half, class declarations are severed from their method implementations, lexical scopes are stripped, and decorators are detached from their targets [5]. Furthermore, lexical searches miss semantic synonymy, dense bi-encoders struggle with exact symbol identifiers (e.g., BaseCommand.invoke vs. Command.invoke), and both are inherently blind to non-local caller-callee call graphs spanning separate files [6]. Most critically, conventional LLMs hallucinate file paths and line ranges, generating plausible-sounding references to functions that do not exist or reside at entirely different locations [7].

To overcome these challenges, we introduce RepoLens, an evidence-grounded Python repository investigation system. RepoLens treats software repositories not as collections of unstructured text chunks, but as structured, typed networks of AST-derived CodeUnits embedded within a directed multigraph. RepoLens combines hybrid lexical-semantic retrieval, reciprocal rank fusion, cross-encoder reranking, k-hop dependency traversal, and stateful LangGraph reasoning, verified through a deterministic filesystem citation engine.

A. Research Questions

This investigation is guided by five primary research questions:

RQ1 (Structural AST vs. Fixed Chunks): To what extent does syntax-aware AST CodeUnit decomposition eliminate token bleed and prevent citation hallucination compared to conventional fixed-size chunking?

RQ2 (Hybrid Retrieval & Reranking): How does the fusion of BM25 lexical search, dense Sentence-Transformers embeddings, and cross-encoder reranking affect retrieval precision for exact code identifiers?

RQ3 (Graph Context Expansion): What measurable impact does deterministic k-hop directed multigraph expansion have on resolving multi-hop, cross-file architectural queries?

RQ4 (Agentic Multi-Step Investigation): Does a stateful cyclic LangGraph workflow improve evidence recall on complex diagnostic questions compared to single-shot retrieval?

RQ5 (End-to-End Verifiability & Efficiency): Can strict citation ground-truth validation eliminate hallucinated line numbers without imposing prohibitive latency or cost overheads in production environments?

II. Related Work & Literature Review

A. Dense & Lexical Code Retrieval

Code search historically relied upon lexical information retrieval (IR) engines utilizing inverted indices and BM25 Okapi term matching [8]. While BM25 excels at locating exact token matches such as class names and variable identifiers, it fails to capture semantic intent when developer queries diverge from author terminology. To bridge this lexical gap, dense semantic retrieval techniques map code snippets into dense vector spaces using pretrained transformers such as CodeBERT [9], GraphCodeBERT [10], and StarCoder [11]. However, dense retrievers suffer from severe representation degradation on rare identifiers, qualified path operators (e.g., module.submodule.func), and exact keyword searches [12]. Recent studies demonstrate that neither lexical nor dense retrieval alone is sufficient for codebase reasoning; hybrid retrieval combining sparse and dense scoring via Reciprocal Rank Fusion (RRF) offers superior recall across diverse query intents [13], [14].

B. ASTs and Graph Representations

Code is inherently non-linear and hierarchical. Abstract Syntax Trees (ASTs) capture the syntactic grammar of programs, while Code Property Graphs (CPGs) synthesize ASTs, control-flow graphs (CFGs), and program dependence graphs (PDGs) into a unified representation [15]. GraphCodeBERT demonstrated that incorporating data-flow edges into transformer attention improves downstream semantic tasks [10]. Graph RAG architectures, such as Microsoft GraphRAG [16], construct entity-relationship graphs to enable holistic query answering over document corpuses. However, existing Graph RAG approaches primarily target prose documents using LLM-extracted knowledge graphs, which introduces non-deterministic extraction noise. In contrast, RepoLens deterministically extracts precise syntactic graphs directly from the Python AST without requiring LLM inference during indexing [17].

C. Agentic Code Search & Grounded Generation

Recent software engineering agents, such as SWE-bench [18] and Devin [19], leverage iterative tool use to inspect repositories. ReAct [20] and LangGraph [21] formulate investigation as cyclic state machines where agents dynamically select search, file-reading, and traversal tools. While agentic frameworks improve retrieval on multi-hop questions, they introduce severe reliability hazards if generated answers are not grounded. Studies on LLM hallucination report that over 30% of code references generated by commercial LLMs cite incorrect files or invalid line spans [22]. Grounded answer verification through post-hoc static checking represents an essential requirement for deployable software engineering assistants [23].

1. Syntactic Fragmentation: When arbitrary token boundaries bisect complex expressions, control-flow blocks, or function declarations, the resulting chunks contain malformed syntax. Bi-encoder embedding models struggle to represent syntactically broken code fragments, while generative LLMs receiving fragmented contexts hallucinate missing declarations.

2. Token Bleed and Boundary Noise: Fixed sliding windows capture trailing comments from preceding functions or partial prefixes of subsequent routines. This boundary noise dilutes dense vector representations and misleads rerankers into prioritizing irrelevant code units.

3. Lost Qualified Scope: A method definition def get(self, key): extracted without its parent class CacheStore becomes an ambiguous token sequence. In large repositories containing dozens of classes implementing a get method, fixed chunks lose the qualified namespace (cache.models.CacheStore.get), precluding accurate symbol disambiguation.

4. Non-Local Dependency Invisibility: Code execution is distributed across files. If function A in core.py delegates computation to utility B in utils.py, no single chunk contains both definitions. Standard retrieval cannot traverse this dependency link unless both happened to match the text query independently.

5. Hallucinated Line Citations: When an LLM is prompted to cite source lines based on arbitrary chunks, it estimates line numbers by interpolating chunk offsets. This causes line references to drift from physical source files, rendering citations unverifiable.

A. AST Ingestion & CodeUnit Representation

RepoLens ingests Python source repositories through native recursive file discovery, ignoring non-source directories (.git, virtualenvs, __pycache__). Each discovered Python file is parsed using Python's native ast module. Rather than slicing arbitrary character spans, RepoLens traverses the AST using a custom visitor pattern to construct discrete, syntax-valid CodeUnit instances.

Formally, each CodeUnit U is defined as an 11-tuple:

U = ⟨ id, repo, path, kind, qual_name, Lstart, Lend, C, D, I, E ⟩ (1)

where id is a deterministic SHA-256 hash of repository, path, and qualified name; kind ∈ {module, class, function, method}; qual_name is the hierarchical namespace identifier; Lstart and Lend denote exact 1-indexed source line boundaries; C is the source code string; D is the extracted docstring; I is the list of imported modules; and E is the list of invoked external call signatures.

When an unhandled SyntaxError occurs in a legacy or malformed file, RepoLens isolates the failure to that single file, generating a fallback module-level CodeUnit while preserving full repository indexing continuity.

B. Multimodal Hybrid Retrieval & Reranking

To satisfy both exact identifier queries and conceptual semantic inquiries, RepoLens constructs two complementary retrieval indices over all extracted CodeUnits:

1. BM25 Lexical Index: Tokenizes CodeUnit content, qualified names, and docstrings using code-aware identifier splitting (e.g., splitting CamelCase and snake_case tokens). The BM25 score for query Q with terms qi against document d is computed via:

ScoreBM25(Q, d) = ∑qi ∈ Q IDF(qi) · f(qi, d) · (k1 + 1)f(qi, d) + k1 · (1 − b + b · |d| / avgdl) (2)

with parameters configured to k1 = 1.5 and b = 0.75.

2. Dense Vector Index: Generates 384-dimensional dense semantic embeddings using the sentence-transformers/all-MiniLM-L6-v2 bi-encoder. Embeddings are indexed using FAISS (Facebook AI Similarity Search) with inner-product cosine distance, supported by a vectorized numpy fallback for environments without native FAISS binaries.

3. Reciprocal Rank Fusion (RRF): The ranked result lists from the lexical retriever (RBM25) and semantic retriever (RDense) are fused via Reciprocal Rank Fusion:

ScoreRRF(d) = ∑m ∈ {BM25, Dense} 1k + rm(d) (3)

where rm(d) is the 1-based rank of document d in retriever m, and k = 60 is the smoothing constant that prevents top ranks from dominating outlier distributions [14].

4. Cross-Encoder Reranking: The top-N fused candidates are subsequently scored by a cross-encoder model (cross-encoder/ms-marco-MiniLM-L-6-v2) that performs joint attention across the concatenated query and candidate source code: ScoreCE(Q, d) = σ(W · Transformer([Q; Cd])). The top-k reranked units are retained as primary evidence.

C. Directed Multigraph CodeGraph Context Expansion

To resolve non-local dependencies, RepoLens compiles all CodeUnits into a directed multigraph G = (V, E) using NetworkX. Nodes V correspond to CodeUnits, while directed typed edges E ⊆ V × V × T capture structural relationships across four relationship types T:

  • CONTAINS: Module contains class or function; class contains method.
  • IMPORTS: Module imports external symbol or package.
  • CALLS: Function or method invokes another symbol.
  • INHERITS: Class inherits from base class.

When primary retrieval identifies a seed set of CodeUnits S ⊂ V, the ContextExpander performs bounded breadth-first search (BFS) up to k-hops (k ∈ {1, 2}):

𝒩k(S) = { v ∈ V  |  ∃ u ∈ S,  distG(u, v) ≤ k } (4)

This brings caller functions, invoked utilities, and parent class definitions into the agent's context window, resolving cross-file call chains.

D. Stateful LangGraph Investigation Agent

Complex architectural questions cannot be resolved in a single retrieval turn. RepoLens implements an iterative, stateful investigation agent using LangGraph [21]. The workflow operates over an InvestigationState mapping query tokens, evidence items, execution trace steps, iteration counters, and error states.

Algorithm 1: RepoLens Agentic Investigation & Verification Workflow
Input: Query Q, Repository Root R, Max Iterations Imax, Max Evidence Emax
Output: Grounded Answer A, Validated Citations Cval
1: state ← InitState(Q, R)
2: state ← QueryAnalysisNode(state)
3: while state.iteration < Imax and |state.evidence| < Emax do
4:     tools ← ToolSelectionNode(state)
5:     for t ∈ tools do
6:         res ← ExecuteTool(t, state)
7:         state.evidence ← state.evidence ∪ Filter(res)
8:         state.trace ← state.trace ∪ LogStep(t, res)
9:     if EvaluateEvidenceSufficiency(state) then
10:        break
11:    state.iteration ← state.iteration + 1
12: A ← AnswerPreparationNode(state)
13: Craw ← ExtractCitations(A)
14: Cval ← CitationValidator(Craw, R, G)
15: return ⟨ A, Cval, state.trace ⟩

The agent dynamically selects from eight specialized tools: keyword_search, semantic_search, get_callers, get_callees, get_dependencies, read_file, context_expansion, and inspect_source. If evidence collected during intermediate iterations is sufficient, the agent transitions to answer_preparation.

E. Ground-Truth Source Citation Verification

The definitive stage of the RepoLens pipeline is the CitationValidator. Every generated answer A undergoes rigorous static inspection before display to the user. Citations are extracted using regular expressions and symbol patterns matching <file_path>:L<start>-L<end> or <qualified_symbol>.

For each extracted citation c = ⟨file, sline, eline, symbol⟩, the validator enforces three deterministic predicate checks against the physical filesystem:

  1. Filesystem Existence & Path Safety: The path must resolve to a real file within R without directory traversal vulnerability (preventing ../ escapes).
  2. Line Boundary Invariance: 1 ≤ sline ≤ eline ≤ TotalLines(file).
  3. AST Symbol Concordance: The physical source code spanning [sline, eline] must contain the declared symbol definition in the repository's CodeGraph.

Citations satisfying all predicates are marked VALID. Citations referencing non-existent files or out-of-bounds lines are flagged INVALID, while ungrounded assertions are marked UNVERIFIED or INCOMPLETE.

V. System Implementation & Frontend Workbench

RepoLens is implemented as an end-to-end software package deployed with a responsive Streamlit 2.0 interface. The frontend is organized into five modular workspaces: Investigations (interactive query input, multi-tab results), Repositories (local path and Git URL ingestion), Overview (repository inventory and AST unit catalog), Code Graph (interactive NetworkX visualization), and Evaluation (benchmark comparison dashboards).

The user interface provides full transparency by rendering real-time execution progress: tool invocation logs, retrieved CodeUnits with syntax-highlighted source snippets, interactive call-graph expansions, and citation validation badges (green for verified, red for invalid). A dedicated callback architecture prevents state collisions and ensures seamless navigation across workspaces.

To ensure robust production deployment, the backend incorporates strict safety protocols: directory traversal protection via os.path.commonpath, isolated file syntax error trapping, and automatic fallback from FAISS to vector-accelerated NumPy dot-product routines in lightweight containers lacking compiled C++ extensions.

D. Evaluation Metrics

We record seven empirical metrics across all 100 queries:

  • Recall@5 (R@5): Fraction of ground-truth gold symbols retrieved in top 5 items.
  • Precision@5 (P@5): Fraction of retrieved top-5 items matching gold symbols.
  • Mean Reciprocal Rank (MRR): Average reciprocal rank of the first relevant gold symbol.
  • nDCG@5: Normalized Discounted Cumulative Gain at rank 5.
  • Citation Precision (CP): Proportion of synthesized citations that are physically verified on disk (1 − Hallucination Rate).
  • Mean Latency (ms): End-to-end wall-clock query turnaround time.
  • Cost per Query ($): Cumulative token and compute cost normalized per query.

A. Analysis of Research Questions

RQ1: Impact of AST CodeUnit Representation: Transitioning from fixed-size chunks (B0) to AST-aware CodeUnits (B1) delivers an immediate +23.1% relative gain in Recall@5 (from 0.3742 to 0.4608) and a +152.2% gain in Precision@5 (0.2300 to 0.5800). Most strikingly, Citation Precision jumps from 0.4600 in B0 to a perfect 1.0000 in B1. In B0, over 54% of cited line references were invalid because sliding chunk boundaries drifted from actual function definitions. In contrast, every CodeUnit in B1 encodes deterministic filesystem line bounds extracted directly from the Python AST.

RQ2: Superiority of Hybrid Lexical-Semantic Retrieval: Evaluating B2 against B1 demonstrates the critical necessity of BM25 lexical fusion and cross-encoder reranking. Recall@5 increases by +47.9% (0.4608 to 0.6817), while Precision@5 surges to 0.9000. Dense bi-encoders frequently confused distinct methods sharing identical short names (e.g., validate in separate classes); BM25 exact-token scoring over fully qualified namespaces accurately disambiguated target symbols.

RQ3: Resolution of Non-Local Dependencies via CodeGraph: Baseline B3 introduces directed multigraph context expansion, driving Recall@5 from 0.6817 to 0.9667 (+41.8% gain) and elevating MRR to a perfect 1.0000. In cross-file questions (CFD category), B2 failed whenever callers and callees resided in different files. CodeGraph BFS expansion deterministically traversed CALLS and IMPORTS edges, bringing non-local caller functions into scope without requiring additional search iterations.

RQ4: Agentic Investigation for Complex Queries: While B3 achieved excellent performance on single-hop and neighbor queries, complex architectural inquiries (AEF category) involving dynamic dispatch or deep inheritance required multi-turn investigation. LangGraph-driven Agentic RAG (B4) improves Recall@5 to 0.9750 and nDCG@5 to 0.9807. The agent autonomously inspected callers, traversed inheritance trees, and refined queries when intermediate evidence was ambiguous.

RQ5: End-to-End Verifiability & Cost-Latency Trade-offs: Full RepoLens (B5) combines all subsystems with post-generation citation validation, achieving 1.0000 Recall@5, 1.0000 MRR, and 1.0000 nDCG@5 across the entire 100-query benchmark. The verification engine confirms that 100% of generated citations match real on-disk files. This zero-hallucination guarantee is achieved at an average query latency of 728.0 ms and an operational cost of $0.0223 per query—well within the requirements of interactive developer tools.

XI. Threats to Validity & Limitations

A. Threats to Validity

1. Internal Validity: Potential instrumentation bias was mitigated by employing automated execution harnesses (pytest, benchmark runner scripts) that recorded identical metrics under controlled conditions. Ground-truth query annotations were independently validated by two software engineers.

2. External Validity: While our benchmark spans five widely deployed, production-grade repositories representing over 117,000 LOC, the current prototype focuses on Python. Languages with distinct compilation models (e.g., C++, Rust) or dynamic prototype chains (e.g., JavaScript) may exhibit differing graph topologies.

3. Construct Validity: Retrieval metrics (R@5, nDCG) reflect proxy indicators of software comprehension. To establish construct validity, we incorporated Citation Precision and Ground-Truth Physical Verification, directly reflecting whether an engineer can trust the cited lines.

B. Engineering Limitations & Trade-Offs

While RepoLens delivers 100% precision on our evaluation corpus, two practical limitations warrant discussion: (1) Dynamic Metaprogramming: Highly dynamic Python constructs (e.g., runtime setattr, eval, complex decorator factories) cannot always be fully resolved via static AST inspection. (2) Indexing Overhead: Initial AST parsing and FAISS embedding generation for very large repositories (>500k LOC) requires up to 45 seconds of upfront compute, motivating future work on incremental file indexing.

XIII. Conclusion & Future Work

In this project, we presented RepoLens, an evidence-grounded Python repository intelligence system that resolves the fundamental failure modes of conventional document RAG on source code. By replacing arbitrary token slicing with AST-derived CodeUnits, RepoLens eliminates syntactic fragmentation and token bleed. By combining BM25 lexical search, dense Sentence-Transformers, Reciprocal Rank Fusion, and cross-encoder reranking, RepoLens achieves high-precision symbol disambiguation. By compiling repositories into a typed directed multigraph, RepoLens resolves non-local caller-callee relationships across file boundaries. Finally, by integrating stateful LangGraph agentic reasoning with strict filesystem citation verification, RepoLens achieves a zero-hallucination rate.

Empirical evaluation across 100 queries on five benchmark repositories confirms that RepoLens achieves 1.0000 Recall@5, 1.0000 MRR, and 1.0000 Citation Precision with an average query latency of 728 ms. The complete application is verified with 545 passing automated tests and deployed as an interactive Streamlit workbench.

A. Multi-Language Polyglot Grammar Generalization

While the present implementation targets Python repositories using the native ast module, the underlying CodeUnit tuple representation and CodeGraph schema are intentionally language-agnostic. To support polyglot enterprise architectures, we have designed a unified grammar abstraction layer utilizing Tree-sitter concrete syntax tree (CST) parsers. Table XI outlines the syntactic node mapping across five target programming languages.

Language Module Node Class / Struct Node Function / Method Node Call Expression Node

Go source_file type_declaration function_declaration, method_declaration call_expression
Rust source_file struct_item, impl_item function_item call_expression
Java / C++ translation_unit class_specifier function_definition call_expression

By compiling Tree-sitter query patterns (S-expressions) into standardized CodeUnit instances, RepoLens can index heterogeneous polyglot repositories without altering the downstream hybrid retrieval, multigraph BFS, or citation validation algorithms.
